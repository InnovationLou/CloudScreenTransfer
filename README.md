# CloudScreenTransfer

通过云桌面显示画面传输文件的 Windows 图形工具。云端显示灰阶数据，物理机捕获并解码；接收进度通过键盘回执返回云端。双击同一个程序，在界面中选择发送或接收。

当前版本 **0.1.0**，只使用图像通道，固定采用此前测试表现最好的一组：**1000×600、2px 四灰阶、5 FPS、RS ECC48**。

## 使用

1. 在云桌面和物理机各放一份 `CloudScreenTransfer.exe`，两端版本须一致。
2. 物理机打开程序，选择“物理机接收”和保存目录。客户端进程默认 `uSmartView_VDI_Client.exe`，其他客户端可修改此项。点击“开始”，接受程序的管理员权限请求。
3. 云端打开程序，选择“云桌面发送”，选择一个文件并点击“开始”。源文件先计算 SHA-256，随后打开数据画布。
4. 在物理机把云桌面客户端切到前台。保持整个数据画布可见，使用 **1:1 显示**。云桌面工作区须能容纳画布和窗口边框；1024×720、100% 缩放是研究中采用的布局。
5. 等待接收端显示“文件完成，SHA-256校验通过”。最终文件出现在所选目录。发送端只有收到接收端的校验完成回执后才显示完成。

回执会点击数据画布顶部的黑色空白处，然后发送一段协议按键。暂时离开云桌面前台、遮挡画布或按住修饰键时会暂停回执；恢复显示后自动重试。画布本身关闭输入法关联，其他窗口设置不受影响。

## 文件支持与续传

- 支持 **0 字节、1 字节和不足一帧的小文件**，末尾按实际字节数写入。
- 文件长度、块号和磁盘偏移均为 64 位。程序流式读写，接收窗口约 5.46 MB，位图仅 3648 字节，内存不随文件大小增长。
- 丢帧、坏包、乱序和重复包由 CRC、纠错和选择性重传处理；进度回执不会代替最终 SHA-256 校验。
- 点击“停止并保存进度”后，再用 **同一源文件、同一文件名和同一保存目录**开始，可以继续接收。文件内容改变会得到新的传输身份。
- 接收端保留 `.cst-*.part` 和 `.cst-*.state`，请保留这些文件以便续传。正常停止会同步保存；突然断电可能回退最近约 2 秒的部分窗口进度，丢失部分会重新传输。
- SHA-256 通过后才生成最终文件；已有同名文件会保留，新文件自动加后缀。再次接收已经完成的同一文件会重新检查其真实 SHA-256。

当前每次传输一个文件。目录或多文件可先自行打包。接收目录所在文件系统需要支持目标文件大小；例如 FAT32 的单文件限制仍然适用。协议偏移最大为 Windows 有符号 64 位文件范围。

## 速度与验证范围

此前最佳 **探针**在 59 秒窗口测得 **96.2121 KB/s**，这里的 KB 是十进制 1000 字节。完整文件协议每帧有效载荷为 `114 × 187 = 21,318` 字节，5 FPS 的理论上限 **106.59 KB/s**。文件信息、回执、重传及两端哈希都会影响实际完成速度，因此不能把探针速度当作本工具的保证。

界面接收速度为本轮新增有效文件字节除以本轮总运行时间，包含等待、哈希和重传；恢复的既有字节不计入新增量。发送端显示接收方已确认的文件进度。

本地验证覆盖协议/纠错、真实文件、取消与续传、同名文件保护、SHA 错误拒绝、真实 Receiver 在 **4 GiB 以上偏移写入**、跨窗口的完整图像闭环，以及隐藏 GUI 控件烟测。未在实际 Win7 云桌面上完成新版本的大文件吞吐复测，也没有把稀疏高偏移测试表述为完整 4 GiB 文件传输测试。

前面的关键实验、参数取舍和音频结论见 [研究记录](docs/RESEARCH.md)，线协议见 [协议说明](docs/PROTOCOL.md)。公开仓库只包含源代码、合成测试和整理后的实验数字。

## 开发与构建

需要 Windows x64、MSVC C++17、CMake 3.20+，以及 vcpkg 的静态 OpenCV `core` / `imgproc`。Reed–Solomon 所需的 libcorrect 源码已随仓库提供。

```powershell
vcpkg install "opencv4[core]:x64-windows-static"
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_and_package.ps1 -VcpkgRoot C:\vcpkg
```

构建脚本执行 Release 构建、CTest、PE 导入检查，输出包含程序、文档、许可证和 SHA-256 清单的便携 ZIP。运行程序不需要 Python、vcpkg 或 OpenCV DLL。脚本默认串行构建，可用 `-Jobs` 调整。

手工构建：

```powershell
cmake -S . -B build -A x64 -DCMAKE_TOOLCHAIN_FILE=C:/vcpkg/scripts/buildsystems/vcpkg.cmake -DVCPKG_TARGET_TRIPLET=x64-windows-static
cmake --build build --config Release --parallel 1
ctest --test-dir build -C Release --output-on-failure
```

目标为 Win7 SP1 x64 / Win10 x64；使用静态运行库、原生 Win32 控件和 Win7 时间 API 兼容处理。PE 检查能发现列出的新 API 导入问题，仍需要实际系统运行验证。升级依赖或编译器后应重新执行检查。
