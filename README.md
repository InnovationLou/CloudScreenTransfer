# CloudScreenTransfer

通过云桌面显示画面传输文件的 Windows 图形工具。云端显示灰阶数据，物理机捕获并解码；接收进度通过键盘回执返回云端。双击同一个程序，在界面中选择发送或接收。

当前版本 **0.2.0**，只使用图像通道，默认沿用此前测通的 **1000×600、2px 四灰阶、5 FPS、RS ECC48**。发送和接收均提供“高级设置”，接收端自动识别发送端的图像编码。

## 使用

1. 在云桌面和物理机各放一份 `CloudScreenTransfer.exe`，两端版本须一致。
2. 物理机打开程序，选择“物理机接收”和保存目录。客户端进程默认 `uSmartView_VDI_Client.exe`，其他客户端可修改此项。点击“开始”，接受程序的管理员权限请求。
3. 云端打开程序，选择“云桌面发送”，选择一个文件并点击“开始”。源文件先计算 SHA-256，随后打开数据画布。
4. 在物理机把云桌面客户端切到前台。保持整个数据画布可见，使用 **1:1 显示**。云桌面工作区须能容纳画布和窗口边框；1024×720、100% 缩放是研究中采用的布局。
5. 等待接收端显示“文件完成，SHA-256校验通过”。最终文件出现在所选目录。发送端只有收到接收端的校验完成回执后才显示完成。

默认保留自动回执：点击数据画布顶部的黑色空白处，然后发送一段协议按键。图像接收只要求画布完整可见；键盘回执需要云桌面客户端在前台。暂时切换应用、遮挡画布或按住修饰键时回执暂停，已可见的图像继续接收；回执恢复后继续协商后续数据。相同等待原因只记录一次，不覆盖传输进度。画布本身关闭输入法关联。

## 高级设置和启动选项

点击“高级设置…”修改参数，点“保存”用于下一次传输。默认自动点击回执继续启用。

| 参数 | 可设置范围 |
| --- | --- |
| 画布宽 / 高 | 900–1920 / 300–1080 像素，须能在云端工作区完整显示 |
| 格子大小 | 2–8 像素 |
| 灰阶 | 2、4、8、16 |
| ECC 纠错字节 | 16、24、32、48、64 |
| 每批帧数 | 16–256，16 的倍数 |
| 发送 / 抓取 FPS | 1–30 / 1–60 |
| 进度 / 协商回执间隔 | 500–30000 / 250–10000 ms |
| 按键保持 / 间隔 | 各 1–200 ms |
| 画面有效时间 | 100–5000 ms；启用回执时至少覆盖一次抓取间隔并增加 100 ms |
| 回执方式 | 自动回执开关、自动点击开关、可选还原鼠标、扫描码 / 虚拟键 / Unicode |

无效组合不能保存。更高灰阶、更快刷新或更弱纠错不保证提速；需要在真实云桌面验证误码和净速度。更改编码会建立独立传输身份及续传记录；只改帧率或回执时间仍可沿用原进度。

“回执后还原鼠标”只在用户没有手动移动鼠标时还原。关闭自动点击时，先手动点一次云端数据画布。也可关闭自动回执，点击接收端“复制回执”，在云端数据画布按 Ctrl+V；它只接受完整且 CRC 正确的回执。不同键盘方式能否通过转发取决于云桌面客户端，默认扫描码沿用已测通的实现。

高级参数以及主界面的 **收发角色、发送文件、保存目录、客户端进程、窗口位置和大小**都会自动保存。通常保存在程序旁的 CloudScreenTransfer.ini（UTF-16，支持中文路径）；程序目录不可写时使用 %LOCALAPPDATA%\CloudScreenTransfer\CloudScreenTransfer.ini。同一程序目录下的不同实例共享这份配置。便携 ZIP 不包含你的个人配置。

## 文件支持与续传

- 支持 **0 字节、1 字节和不足一帧的小文件**，末尾按实际字节数写入；小文件或元数据重复发送时主体图像可能不变。
- 文件长度、块号和磁盘偏移均为 64 位。程序流式读写，默认接收窗口约 5.46 MB、位图 3648 字节；自定义编码按每批容量计算位图，内存不随文件大小增长。
- 丢帧、坏包、乱序和重复包由 CRC、纠错和选择性重传处理；进度回执不会代替最终 SHA-256 校验。
- 点击“停止并保存进度”后，再用 **同一源文件、同一文件名和同一保存目录**开始，可以继续接收。文件内容改变会得到新的传输身份。
- 接收端保留 `.cst-*.part` 和 `.cst-*.state`，请保留这些文件以便续传。正常停止会同步保存；突然断电可能回退最近约 2 秒的部分窗口进度，丢失部分会重新传输。
- SHA-256 通过后才生成最终文件；已有同名文件会保留，新文件自动加后缀。再次接收已经完成的同一文件会重新检查其真实 SHA-256。

当前每次传输一个文件。目录或多文件可先自行打包。接收目录所在文件系统需要支持目标文件大小；例如 FAT32 的单文件限制仍然适用。协议偏移最大为 Windows 有符号 64 位文件范围。

## 速度与验证范围

此前最佳 **探针**在 59 秒窗口测得 **96.2121 KB/s**，这里的 KB 是十进制 1000 字节。默认完整文件协议每帧有效载荷为 `114 × 187 = 21,318` 字节，5 FPS 的理论上限 **106.59 KB/s**。文件信息、回执、重传及两端哈希都会影响实际完成速度，因此不能把探针速度当作本工具的保证。

界面接收速度为本轮新增有效文件字节除以本轮总运行时间，包含等待、哈希和重传；恢复的既有字节不计入新增量。发送端显示接收方已确认的文件进度。

本地验证覆盖协议/纠错、真实文件、取消与续传、同名文件保护、SHA 错误拒绝、真实 Receiver 在 **4 GiB 以上偏移写入**、跨窗口的完整图像闭环，以及隐藏 GUI 控件烟测。发送端烟测会实际执行文件哈希、编码和 GDI 画布，连续验证两次启动失败、渲染后非标准异常、空文件、1 字节文件和普通文件的停止后重启，并检查窗口/GDI 资源释放。未在实际 Win7 云桌面上完成新版本的大文件吞吐复测，也没有把稀疏高偏移测试表述为完整 4 GiB 文件传输测试。

0.2.0 另验证了八组自定义编码的真实图像/文件闭环、丢帧与续传，全部参数的中文 INI 保存、原子替换失败保护、主界面恢复以及高级设置控件的选择、保存、默认值和布局边界。高灰阶在实际云桌面上的稳定性仍须实测。

前面的关键实验、参数取舍和音频结论见 [研究记录](docs/RESEARCH.md)，线协议见 [协议说明](docs/PROTOCOL.md)。公开仓库只包含源代码、合成测试和整理后的实验数字。

## 开发与构建

需要 Windows x64、MSVC C++17、CMake 3.20+，以及 vcpkg 的静态 OpenCV `core` / `imgproc`。Reed–Solomon 所需的 libcorrect 源码已随仓库提供。

```powershell
vcpkg install "opencv4[core]:x64-windows-static"
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_and_package.ps1 -VcpkgRoot C:\vcpkg
```

构建脚本执行 Release 构建、CTest、PE 导入检查，输出包含程序、文档、许可证和 SHA-256 清单的便携 ZIP。运行程序不需要 Python、vcpkg 或 OpenCV DLL。脚本默认串行构建，可用 `-Jobs` 调整。

手工构建：

```powershell
cmake -S . -B build -A x64 -DCMAKE_TOOLCHAIN_FILE=C:/vcpkg/scripts/buildsystems/vcpkg.cmake -DVCPKG_TARGET_TRIPLET=x64-windows-static
cmake --build build --config Release --parallel 1
ctest --test-dir build -C Release --output-on-failure
```

目标为 Win7 SP1 x64 / Win10 x64；使用静态运行库、原生 Win32 控件和 Win7 时间 API 兼容处理。启动时先禁用 OpenCV 并行线程，GDI 灰阶转 BGRA 使用逐像素顺序转换，以避开限制较多的云桌面上的 Microsoft Concurrency 调度器。PE 检查能发现列出的新 API 导入问题，仍需要实际系统运行验证。升级依赖或编译器后应重新执行检查。

## 0.1.1：发送端启动异常修复

0.1.0 遗漏了老 `libcimbar` 云桌面发送端及屏幕探针的 `cv::setNumThreads(1)` 配置，首次 GDI 显示的 `cvtColor` 会进入静态 OpenCV 的 Concurrency 并行路径。这与云端报告的 `Unknown Exception` 和再次启动崩溃相符；缺少云端异常日志，仍需在原 Win7 云桌面确认根因。

0.1.1 在创建任何工作线程前设置单线程图像运行环境，发送端直接生成完全相同的 BGRA 像素。工作线程及回执线程处理非标准 C++ 异常，失败后清理画布、回收线程并恢复“开始”按钮。程序目录的 `CloudScreenTransfer.log` 记录启动版本、任务结果、失败阶段和异常类型；目录不可写时回退到 `%TEMP%\\CloudScreenTransfer-进程号.log`。硬件异常会记录代码及地址并保持系统的异常处理行为。
